# LuaSitter test suite

Automated tests for LuaSitter1 and LuaSitter2. They run the real `.luau` scripts offline in [rezless](https://github.com/i-doll/rezless) (version 0.13.0), a Second Life script simulator that runs SLua in SLua's own VM, with [Vitest](https://vitest.dev).

**These tests do not replace testing in-world.** rezless simulates Second Life closely, but not exactly (see [Differences from Second Life](#differences-from-second-life)). Every change still needs to be tested in-world by a human before a pull request; see [CONTRIBUTING.md](../CONTRIBUTING.md).

## Running the tests

You need [Node.js](https://nodejs.org) 22.12 or newer.

```sh
node test/run-tests.mjs            # run every test (installs rezless and vitest on the first run)
node test/run-tests.mjs paging     # only test files whose path contains "paging"
node test/run-tests.mjs --install  # reinstall the dependencies first
node test/run-tests.mjs --coverage # also show which lines of the scripts the tests ran
```

`npm test` in this folder does the same. The script prints a PASS/FAIL line per test file and a total, and writes the full results to `test/results.json`.

With `--coverage`, it also prints the share of statements, branches and functions of each `.luau` script that the tests ran, and writes a line-by-line report to `test/coverage/html/index.html` (plus `lcov.info` for editor coverage plugins). Use it to find what is not tested yet.

On Windows, run it from any shell. The script works around a Vitest bug that breaks when the drive letter of the working directory is lower case (`d:` instead of `D:`).

## How the tests work

`helpers/furniture.ts` builds a piece of furniture: a linkset with the scripts, notecards and animations a test asks for, in a rezless World with avatars. It gives the tests short helpers (`sit`, `stand`, `touch`, `click` a dialog button, `say` on a channel, `playing` animations, `broadcast` a link message, `setNotecard` to edit inventory, `rezzed` props). Props are real objects rezzed from the furniture's inventory, with their scripts running, and the sit scripts can be put in a child prim (`childScripts`, `contentsLink`).

Scripts whose presence is all that matters (for example 14 extra `[LS]sit N` copies when only `[LS]select` is under test) are loaded as empty placeholders.

## Differences from Second Life

rezless simulates Second Life closely, but not in everything LuaSitter uses. The harness (`helpers/furniture.ts`) fills these gaps; each is explained in a comment there too:

- **Seated avatars as links.** In Second Life a seated avatar becomes an extra link of the object, and LuaSitter finds its sitters that way (`llGetNumberOfPrims`, `llGetLinkKey`). rezless doesn't model that, so the harness mocks both functions in every script. An avatar a script unseats (`llUnSit`) stops being a link at the next 100 ms step of `settle`.
- **Automatic permissions.** Second Life grants animation permission to a script automatically when the avatar it asks is sitting on the object. The harness grants those requests at every 100 ms step of `settle`.
- **Sitting when the sit target is taken.** In Second Life a second avatar can still sit on an object whose sit target is taken (AVsitter1 relies on this). rezless seats an avatar only on a free prim, so the harness picks a free prim, and fails the test if rezless refuses.
- **Inventory changes.** rezless does not send `changed` (`CHANGED_INVENTORY`) when a test edits inventory, so `setNotecard` and `setItem` send it to the scripts in that prim.
- **Avatar chat.** There is no "avatar says" call, so `say` delivers the message to the matching listens of every script.
- **RLV relay.** No relay is simulated. The RLV tests check the commands the furniture says to the relay, and answer `@getstatus` the way a relay would (`relayAnswers` in `rlv.test.ts`).

Things rezless does as Second Life does, which tests have to allow for:

- **Forced delays.** Functions with a forced delay in Second Life also delay in rezless: `llDialog` 1 s, `llRezAtRoot` 0.1 s. A timer that comes due while a handler is held by such a delay runs right after it. For example, choosing a pose from the LuaSitter1 menu calls `llDialog`, so the 0.5 s wait before stopping the old animation is already over when the dialog answer returns; the timing test plays the pose by link message instead.
- **Dialog answers settle.** `answerDialog` runs the listen handlers to completion, including those forced delays, so it can advance the clock.
- **Link numbers.** In a one-prim object `llGetLinkNumber()` is 0, and several scripts only accept link messages from their own link number. Tests that fire `link_message` directly pass `sender_num` 0 there (or `script.host.linkNumber`).
- **Giving items.** Giving an item to a prim that already has one with that name adds a numbered copy (`LSpos 1`). See the updater test.
- **Timing.** A link message is handled on the next event, and some scripts wait briefly (for example the old animation stops a moment after the new one starts). Tests let time pass (`settle`, `advance`) before checking.

A difference in strictness:

- rezless refuses a `uuid` where Second Life's SLua definitions accept a `uuid` or a string (for example `ll.PlaySound`, `ll.StopAnimation`). The scripts pass strings there, which works in both, except where the helpers stop the animations from `ll.GetAnimationList` (uuids): those tests mock `llGetAnimationList` to return strings.

Not covered (see `--coverage`): `[LS]object` attaching a prop through an Experience (the harness gives rezzed props no Experience), the one-day self-delete of the LuaSitter2 helper (`[LS]helperscript`; the LuaSitter1 helper's 7-day one is tested), the `USES_PROPS` lines of `[LS]LockGuard` (tested with a changed copy of the script, which coverage does not count), and defensive branches no setup reaches. How animations look, exact positions in-world, the camera the viewer shows, and RLV viewer behaviour can only be checked in-world.

## Adding tests

Put new test files in `luasitter1/`, `luasitter2/` or `all-scripts/`, named `*.test.ts`. A test that fails because of a rezless limit, not a LuaSitter bug, should work around it in the harness with a comment explaining the difference from Second Life.
